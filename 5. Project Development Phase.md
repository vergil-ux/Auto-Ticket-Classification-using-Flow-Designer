# Project Development Phase

This is where the design actually got built. I'll walk through it in the order I did it — table first, then fields, then the dependency logic, then the actual automation in Flow Designer.

## Step 1: Creating the custom table

1. Opened **All menus** → searched for **Tables**.
2. Under **System Definition**, clicked **Tables**.
3. Clicked **New** in the top right.
4. Set the Label to `Incident WorkFlow`.
5. Unchecked **Create module** (didn't need a separate navigation module for this).
6. Saved the form.
7. Went into **Controls** and enabled **Auto Number**.
8. Saved again.
9. From **Related Links**, clicked **Show Form**, then opened the form's context menu and went into **Form Designer** to start adding fields.

## Step 2: Creating the fields

I added the following fields to the table, with the data types and choice values from the design phase:

| Field Label | Type | Reference / Choice |
|---|---|---|
| Number | Auto Number | — |
| Caller | Reference | `sys_user` |
| Category | Choice | Network, Hardware, Access, Performance |
| Subcategory | Choice | Wi-Fi, Projector, Forgot Password, Slow Computer |
| Short Description | String | — |
| Description | String | — |
| State | Choice | New, In Progress, On Hold, Resolved, Closed |
| Assigned Group | Reference | `sys_user_group` |
| Assigned To | Reference | `sys_user` |

For Category, Subcategory, and State, I added the choice list values directly through the field's configuration on the form, then saved and reloaded the form to confirm the dropdowns showed the right options.

## Step 3: Making Subcategory depend on Category

This was the fiddliest part of the backend work. Steps:

1. Opened the table form and right-clicked the **Subcategory** field.
2. Selected **Configure Dictionary**.
3. Under **Related Links**, opened **Advanced View**.
4. Went to the **Dependent Field** section and checked **Use dependent field**.
5. Set the **Dependent on field** to `Category`.
6. Saved the dictionary entry.
7. Scrolled down to the **Choice** section and mapped each Subcategory value to the Category value it should appear under:
   - Wi-Fi → Network
   - Projector → Hardware
   - Forgot Password → Access
   - Slow Computer → Performance
8. Saved.

After this, opening the form and picking a Category correctly filtered the Subcategory dropdown to only the relevant option — no more mismatched pairs like "Network" + "Projector".

## Step 4: Building the automation in Flow Designer

Once the table itself was solid, I moved on to the actual classification logic.

1. Went to **All menus** → searched for **Flow Designer**.
2. Under **Process Automation**, opened **Flow Designer**.
3. Clicked **New** → **Flow**.
4. Named it `Auto Classify School IT Tickets`, Application: `Global`.
5. Clicked **Build Flow**.

### Trigger

- **Trigger type:** Record Created
- **Table:** Incident WorkFlow
- **Condition:** Category is empty

This means the flow only fires on brand-new tickets that haven't already been categorized — so it won't try to re-run on something that's already been handled.

### Branch 1 — Wi-Fi / Network

- Added an **If** condition, labeled it "SD is Wi-Fi or Network".
- Condition 1: Short Description **contains** "Wi-Fi"
- Condition 2 (OR): Short Description **contains** "Network"
- Action: **Update Record** on Incident WorkFlow → set Category = `Network`, Subcategory = `Wi-Fi`.

### Branch 2 — Projector

- Added an **Else If**, labeled "SD is Projector or Hardware".
- Condition: Short Description **contains** "Projector"
- Action: **Update Record** → Category = `Hardware`, Subcategory = `Projector`.

### Branch 3 — Password / Login

- Added another **Else If**, labeled "SD is Forgot Password".
- Condition: Short Description **contains** "Forgot Password"
- Action: **Update Record** → Category = `Access`, Subcategory = `Forgot Password`.

### Branch 4 — Slow Computer

- Added a final **Else If**, labeled "SD is Performance".
- Condition: Short Description **contains** "Slow Computer"
- Action: **Update Record** → Category = `Performance`, Subcategory = `Slow Computer`.

### Email notification

After the classification branches, I added a **Send Email** action:

- **To:** Caller → Email
- **Subject:** "Your Request for the issue has been submitted."
- **Body:** A short confirmation message letting the caller know their ticket was received.

### Activating

Once everything was wired up, I clicked **Activate** on the flow so it would actually start running against new records instead of just sitting there in draft.

## A note on the approach

I deliberately kept this rule-based rather than reaching for ServiceNow's Predictive Intelligence / ML tooling. For a school helpdesk with a handful of very predictable issue types, a transparent If/Else If chain does the job without needing training data, retraining, or any ML overhead — and it's something the next person can open up and understand in five minutes.
