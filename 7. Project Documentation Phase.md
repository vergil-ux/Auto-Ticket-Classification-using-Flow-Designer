# Project Documentation Phase

## Wrapping up the Update Set

Once testing confirmed everything was working, the last real task was packaging the work up so it could actually be moved somewhere else or handed off.

**Steps I followed:**

1. Went to **All menus** → searched **Local Update Sets**.
2. Under **System Update Sets**, opened **Local Update Sets**.
3. Opened `Project Update Set` (the one created back in the Requirement Analysis phase).
4. Changed the **State** from `In Progress` to `Complete`.
5. Saved the form.
6. Under **Related Links**, clicked **Export to XML**.
7. The Update Set downloaded as an XML file to my machine, which I could then share (over email, WhatsApp, a shared drive, whatever's convenient) or import into another instance.

## How to set this up on your own instance

1. Import the exported Update Set XML into your ServiceNow instance and preview/commit it.
2. Confirm the `Incident WorkFlow` table came through with all fields and the Category/Subcategory dependency intact.
3. Open the `Auto Classify School IT Tickets` flow in Flow Designer and check it's **Active**.
4. Create a test record on Incident WorkFlow with a Short Description like "WiFi not working" and confirm Category/Subcategory fill in and an email goes out.
5. If it's not classifying anything, double check the trigger condition (`Category is empty`) and that the flow is actually active, not just saved as a draft.

## Maintaining it going forward

- To add a new issue type: add the new Category/Subcategory choice values to the table, extend the dependency mapping, then add one more Else If branch in the flow for the new keyword(s).
- To adjust wording it catches (e.g., add "internet" alongside "Wi-Fi"), just add another OR condition inside the relevant If/Else If branch — no need to touch anything else.
- If tickets start showing up uncategorized, it usually means the caller's wording didn't match any of the current keyword conditions — worth reviewing a batch of uncategorized tickets periodically to see if a new keyword pattern needs to be added.

## Closing thoughts

This project set out to take one repetitive, manual step — reading a ticket and deciding what category it belongs in — and hand it off to a simple, transparent piece of automation. Between the dependent Category/Subcategory fields and the keyword-based Flow Designer logic, tickets now get classified the moment they're created, and the caller gets an automatic confirmation instead of silence. It's a small, no-code solution, but it's exactly the kind of thing that adds up to real time saved for a small IT team, and it's simple enough that anyone can pick it up and extend it later — no scripting or machine learning required.
